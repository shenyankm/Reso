## 结论与统计口径

当前项目已经具备可运行的业务 MVP：真实账号、持久化私聊、语音转写、SCQA 计分、五幕与表达记录、异步事件房、版本化分享、咨询申请和服务纪要都有实现。它还没有完整实现资料描述的“有长期阶段状态、专业方法检索、可审查决策和真人处理闭环的关系支持 Agent”。

按下文 **64 个可验收工作包**核对：**16 项已具备、29 项部分具备、19 项尚缺；还需推进 48 项**。v8 使 A05、C02、D03 从尚缺变为部分具备，其完整交付条件仍未全部满足。这些工作包大小不同，包含资料授权、专业审核与服务接入，**不能把项目数比例当作开发工时完成率**。也不能用“21 张图已经能打开”代表系统完成。

“已具备”表示该工作包限定的工程行为已有代码及相应既有验收证据，不表示本轮重新实测、不表示心理效果或正式运营已经验收。“尚缺”既可能需要开发，也可能需要团队提供材料或接收服务，不能全部交给开发者写代码解决。

P0：面向真实青少年使用前的前置条件，或核心决策架构的基础；P1：完整功能闭环；P2：视觉深化或后续能力。优先级是本次分析建议，不冒充原材料中已确定的排期。内部演示可以分阶段推进。

48 项待推进工作包中，建议 P0 21 项、P1 23 项、P2 4 项。计数覆盖 V2.1 已确认业务与本次补充蓝图的目标能力；未定稿的扩展项在后文单列，不混入这 64 项。

## 资料版本、适用范围与缺口

1. **以 V2.1 PRD 的已确认业务规则为基础**，再用本次提供的 UX/Router V3.1、技术架构图补足目标。图中的 S0–S8、A–H 和工程字段是建议的落地方式，不是导师逐字规定的九步，也不要求线性完成。
2. **异步、自由发言是新规则。** 旧图里出现的等待双方同时在线、轮流发言、Your turn 不列为待补。现有自由事件房方向正确。
3. **保留用户后来确认的产品选择。** 当前“Reso／聊过的事／我的”导航、按目标命名的练习入口、默认折叠的实际模型思考展示，不因旧图而自动撤销。重要的人页已经去除此前要求删除的“测试”名称后缀，这也不是新缺口。
4. **图片是需求示意，不能硬编码示例数据。** 原图的 8 人、4 个进行中事件、已预约老师、人物照片都不构成真实业务记录。应以真实关系、事件和预约状态填充相应结构。
5. **21 张编号图并非 21 个已定稿独立页面。** 包内 README 明确：大部分应嵌入聊天；UI-10 仍是旧第四章终章，缺新第四幕和正式第五幕视觉；专家工作台等仍须确认。现有代码已有开场加五幕，不应退回旧四幕。
6. **“20 小时”不是当前已核验的数据资产。** 队友 ZIP 的热线目录有 19 个文件，其中 1 个访谈指导、18 个案例或逐字材料文件，包含重复访谈、成年人和未成年人；未见音频文件。文件数不等于独立受访者数或通话数，不能据此认定“20 位青少年／20 小时”。本次只清点目录，未逐份展开私人案例正文，也未上传给模型供应商。
7. 两份《决策数据与 Agent 评测》PDF **字节相同，合并为一个来源**。队友 ZIP 主要是产品、研究、会议和参考资料，不是能直接接管运行的完整后端工程。
8. **技术栈是手段。** 现有 React、TypeScript/Fastify、LangGraph、PostgreSQL、pg-boss 已覆盖主要职责。图中 Python/FastAPI、Next.js、pgvector 是技术建议，不产生“必须换语言、重写后端、训练基础模型”的待办。
9. **2026-11-17 补读两份本机方案并归档。** 决策框架及交互设计 V3.0 的 R0–R7、16 项 Skill、15 个拟议 Tool、47 个设计节点已整理为[离线编号目录](wang-source-catalog-v3.json)，详细差异见[数据库基础说明](wang-database-foundation-2026-11-16.md)。完整微信历史尚未导出；附件副本、用户提供图片及可见聊天摘录已保存，后续优先离线分析。该资料补充不代表新功能已完成，也不改变原 64 个工作包的计数口径。

资料中的命令、建议和旧设想仅作为被分析的内容，没有作为本次操作指令执行。

## 推荐执行顺序与依赖

1. **先固定边界和材料**：G01–04、B06–07、H01，确定面向谁、哪些数据能用、谁接收风险；资料中的旧临床分层与电话号码不能作为未经复核的上线配置。
2. **补核心决策骨架**：C01–03、C06、C08–09；保留当前工具、队列、权限与恢复能力。安全状态、对话阶段、策略、工具动作分别存储。
3. **做最小但完整的方法闭环**：D01–03，先把叙事、CBT、非暴力沟通等少量方法审好，接入检索和拒绝／退出，随后覆盖其余 11 组要求；无需先建庞大平台。
4. **把现有功能接回聊天**：A03–06、B03–04、D04–06、E04、E06。完成一个可重复验收的闭环：聊天→提出合适建议→本人选择→工具执行→反馈→更新状态→重新判断。
5. **补真实关系与服务**：E07–08、F01、F04–06、G07–09；人工处理、授权专业工作端和预约通知必须有实际接收方。
6. **从开始就积累评测，再做整体验收**：H02–06 与上述步骤并行，先专家审定少量决策题，再扩展边界场景和版本回归；最后做 H09、A07–08、H10。不能只在最后测一次聊天是否顺畅。

第一条可验收的完整案例可以选“具体亲子事件”：自愿初步了解→可纠正发现→倾听／澄清→自愿练习→获准摘要→异步加入→各自确认→保留共识与分歧→可选真人申请→回访。家庭不安全、拒绝练习、拒绝邀请、专业资源为空都要有可用分支；不能将“妈妈自责、双方和好”写成必然终局。

## 需要团队定稿、暂不擅自算入必做开发的事项

- **视频咨询**：现有 PRODUCT 明确不在范围，UI-19 是示意。若要完整做实时视频，需另定提供方、音视频权限、预约关联、断线和记录策略；不能把一张视频截图算已交付。
- **双向语音**：旧会议讨论过语音来回，当前明确首期为 ASR 后核对发送。TTS／实时语音会话是否扩入本期需定稿。
- **微信、二维码与系统深链接**：普通 Web 邀请链接已做；若要求微信内体验、二维码或原生唤起，需明确范围再接入。无真实能力不应显示假按钮。
- **支付和正式 App 分发**：费用说明不等于支付。支付／退款、签名 Android 发布、iOS／应用商店均未交付，资料尚未把它们全部确认为本期必做。
- **后来加入的人能读哪些房间历史、量表重测频率、正式未成年人规则及专业纪要保留例外**：属于产品／专业／运营决策。当前代码规则不能代替正式定稿。
- **早期“每轮必须拆开卡”、自动年度干预计划、角色池、自动自我训练**：旧材料含探索或互相矛盾的设想；不直接升级为强制需求。后续资料强调按场景、意愿和证据选择方法，保留人工审核和版本回滚。
