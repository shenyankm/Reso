# Reso 产品需求

整理日期：2026-11-12。依据[项目分析会话](codex://threads/01a1d046-d5fc-7562-94e1-08389a28687c)全部 13 轮讨论，以及其中对 PRD V2.1 的解读。本文件是会话交接稿；原 PRD 约束、讨论建议与待确认问题分别列明，不能作为已签署的研发验收定稿。

## 产品定位与目标人群

Reso 为青少年提供心理支持与关系沟通辅助，帮助他们说清具体烦恼、理解自己的感受、练习表达需要，并在自愿时邀请家长共同沟通。产品不承担诊断、治疗或紧急救助服务。

| 人群 | 角色与需求 |
| --- | --- |
| 初高中学生 | 核心使用者，处理学业、亲子、同伴关系与情绪困扰；早期资料更聚焦初三至高三，最终年龄范围待确认 |
| 父母等重要关系人 | 经邀请参与某一事件，表达自己的看法并核对理解 |
| 真人心理咨询师 | 提供进一步支持，按服务授权读取必要资料 |

最具体的首期场景是青少年与父母之间的理解和沟通。使用者、付费者与采购方是否分别为学生、家长、学校或机构，尚未确定。

核心过程：**倾诉具体事件 → 澄清事实、解释与感受 → 核对理解 → 尝试表达或练习 → 自愿有限分享与共同沟通 → 回访变化。** 用户可以拒绝、暂停、纠正或退出，不要求线性完成。

## 产品形态

用户提出先做 React＋TypeScript 移动端 Web，后续使用 Tauri 2 发布 App。家长保留 Web 邀请入口，专业人员工作台建议使用独立 Web 界面。

主要入口是聊天与“我的关系”。问卷、小发现、练习、邀请及咨询申请优先在聊天流中通过卡片展开；事件房间具有独立链接与权限。21 张 UI 表示多种状态与分支，不应直接拆成 21 个独立页面。

当前工程覆盖、测试依据与未完成项见 [PRD 实现对照](prd-implementation.md)；本文件中的需求不自动视为已交付。

## 功能需求

### F1 初步了解与 SCQA

- 用户可自愿完成初步了解和问卷；拒绝或暂停后仍应能够继续获得聊天支持，具体入口分支需补充验收规则。
- 会话材料中的 SCQA 为 24 题、四个领域、上下行两个方向，共八个分量表；不合并总分，不用于判断抑郁程度或直接归责家长。
- 正式计分使用确认过的固定题本、选项、版本及确定性算法，不能由模型临时改题或猜分。
- “一个小发现”呈现一条待核对的理解，支持“像／不像／修改”，再按用户意愿进入具体事件。
- PRD V2.1 的权限约束是：原始作答与计分仅供初步了解角色读取；1v1 支持读取经用户确认的初始摘要。早期讨论中让后续私聊直接读取分量表的建议已被收紧。

### F2 私聊与心理学练习

Reso 私聊帮助用户区分发生的事、自己的解释、感受和需要；保存获准记录的进度，便于下次继续。工具包括非暴力沟通、心理剧或情境小剧场、叙事练习，以及跳转合法外部音乐服务的陪伴功能。

PRD 中的五幕示例围绕“考试进步后，妈妈说就差几分”展开：

| 幕次 | 名称 | 内容 |
| --- | --- | --- |
| 开场 | 把这段经历画出来 | 介绍练习并征求意愿，不计入五幕 |
| 第一幕 | 回到那天 | 还原开心到受伤的变化 |
| 第二幕 | 两种声音 | 区分妈妈的原话与孩子心中的解释 |
| 第三幕 | 没有放弃的时刻 | 回看补课、补题等真实付出 |
| 第四幕 | 这些画里的我 | 同时看见开心、受伤与坚持的自己 |
| 第五幕 | 我的故事 | 保存用户认可的新叙事 |

练习需要上一幕、继续、修改、暂停、下次接着聊和保存故事等状态。保存内容默认私人，不能自动共享完整故事。

五幕是通用方法还是特定演示脚本，以及其他事件如何适配，仍需明确。“叙事小练习”与“心理剧”的正式分类和命名也需统一。

### F3 邀请与多人自由沟通

- 先让用户确认想表达的需要、事件名称和分享摘要，再发送邀请。
- 邀请已发送不等于对方已加入。受邀者需查看事件名称与分享范围，并能够接受或拒绝。
- 支持异步加入与自由发言，不设置强制轮流发言锁；Reso 可以选择暂不发言。
- 房间仅使用公开消息与有效授权下的分享快照，不自动获得私人聊天、原始问卷或后来新增的私人内容。
- 双方分别核对自己的感受和理解；一方确认不等于双方共识，允许意见不同或没有和解。
- 待邀请、待加入、已加入、拒绝、取消、失效和退出需要明确状态。妈妈退出后不再接收新房间消息，重新加入需满足当时的授权条件。

“妈妈是在自责”只能是待核实假设。不能按示例剧情要求真实家长表达懊恼、自责或立刻认同孩子。

### F4 真人支持与转接

- 聊天中推荐 2–3 位真实咨询师，展示身份、资质、流派、擅长领域、服务方式、公益或费用信息及具体推荐理由。
- 用户可选择分享某件事的摘要，或不分享聊天内容；不分享也可以申请服务。
- 推荐、提交申请、待处理、接单、协商时间、预约确认、完成及纪要分别处理，补齐拒绝、取消、失败和无档期分支。
- 专业端仅看到申请必要信息与有效授权内容；向谁开放咨询纪要、是否向家长分享，需单独确认。
- UI-19 中的视频咨询属于探索性界面内容，不纳入当前开发范围。

### 我的关系

包含“一件小事／重要的人”两个 Tab，用于找回事件、相关人物、理解摘要与成长记录。人物详情不自动创建两人私聊，成长卡片默认私人。

无事件时显示“还没有记录的小事”，提供“和 Reso 聊聊”入口；不预置虚假事件或数字。

### 通用交互

- 语音首期为转写成文字、用户修改或确认后发送，不据此推导实时语音通话。
- 问卷、聊天、练习与事件支持中断和恢复；发送失败、断线与重复操作有明确反馈。
- 邀请失效、权限撤回及预约失败等情况在原会话或轻量面板中解释并提供下一步。

## 事实记录与授权边界

| 记录类型 | 规则 |
| --- | --- |
| 原话 `user_quoted` | 保留说话人、来源与上下文，不改写成第三方已确认事实 |
| 模型推测 `model_inference` | 明示不确定性，支持认可、否认与修改 |
| 单方确认 `participant_confirmed` | 记录确认人、时间和版本，仅代表该方陈述 |
| 双方确认 `jointly_confirmed` | 双方明确同意后才能成为共识，保留分歧与修订记录 |
| 用户修正 `user_corrected` | 后续使用当前确认版本，并保留更正历史 |

私聊、各方陈述、共享房内容和专家服务资料分域保存。摘要与附件继承来源权限，分享使用有对象、范围和版本的快照。模型建议、前端按钮或邀请链接都不能替代服务端鉴权与明确授权。

用户应能查看自己的记录和当前分享范围，并按产品规则撤回授权、删除或导出资料。撤回后阻止后续 API 读取；不能承诺收回他人已经阅读或依法保留的副本。后加入者的历史可见范围与撤回对既有房间历史的具体影响仍待定稿。

原始语音默认仅用于转写，录音留存另定政策；私人咨询内容不进入通用知识库。训练样本等其他用途需单独明示授权。

## 安全支持

PRD 要求依据经过审核的规则处理风险信号，必要时优先转向人工支持。当前确认的安全 UI 是私人聊天内的求助卡，包含可信任成年人、校园心理支持及专业和当地资源入口。

年龄与监护同意、危机阈值、保密例外、通知规则及当地求助渠道需专业和法律审核。实际转人工还要明确接收者、响应方式、无人接收时的处理和后续状态。SCQA 不能作为危机或疾病的单一判定工具。

## 优先级与设计依据

| 优先级 | 范围 |
| --- | --- |
| P0 | 必要同意、消息域隔离、事件归属、分享快照、成员校验、撤回与安全转介 |
| P1 | 私聊、SCQA、小发现、五幕练习、事件记忆、邀请与多人房 |
| P1 | 我的关系、重要的人、成长记录与无事件空状态 |
| P1 | 真实咨询师推荐、独立授权、申请与真实预约状态 |
| P2 | 音乐收藏、动效、更多练习模板、付费服务与专业端深化 |

PRD V2.1 当前仅明确确认两张新增 UI：聊天内安全求助卡、“我的关系”无事件空状态。其它探索性独立页面不能批量升级为研发定稿。UI-10 仍是旧第四幕终章，缺少新第四幕，需更新到五幕版本。

## 验收重点与待补需求

原 PRD 结构较完整，仍需补本期交付范围表、状态与异常规则表，以及 Agent 场景验收集。应优先覆盖：

1. 拒绝问卷、否认小发现、退出练习后，仍能继续聊天或恢复获准保存的进度。
2. 用户纠正后，后续回复、事件记忆和卡片不再把被否认的假设当成确认事实。
3. 一方确认只更新该方版本，另一方未确认时不显示为双方共识。
4. 拒绝分享或撤回授权后，其他参与人、房间及专家不能继续通过 API 读取无权资料。
5. 邀请不等于加入、申请不等于接单、接单不等于预约完成；重复点击不重复执行。
6. 断线、邀请失效、预约失败、房间并发发言及双方冲突均有可观察的处理结果。
7. 高风险信号进入经过审核的安全路径；只采用当前确认的 UI。

还需确定：确切年龄范围、问卷入口规则、五幕适配规则、后加入者历史权限、撤回后的历史可见性、咨询服务目录与收费、人工支持运营和商业模式。
