# M1a/M1 分批实施、回填、回滚与权限验收方案

2026-11-17。基于 [V2.3 目标设计](database-design-v2.md)、[字段模型](database-model-v2.json)、[九项修复台账](database-nine-fixes-2026-11-17.md)及当前 0001–0007 源码制定。本文件是已完成的实施方案；**没有创建正式迁移文件、执行 SQL、读取真实业务数据、回填、修改数据库角色或切换运行层。** GitHub 源码发布与数据库部署分别执行。

## 1. 已核对的实施限制

| 现有实现 | 对后续实施的约束 |
| --- | --- |
| [migrate](../server/migrations.ts) 把所有未执行文件放在一个事务，使用 advisory lock 和逐文件 SHA-256 | 一次投放一个已验收批次的文件集；不能把五个累计草案一起复制到 migrations。大回填另做有游标的维护任务，不塞入 DDL 事务 |
| verifyMigrations 严格要求文件集合和数据库记录完全一致，API/Worker 启动都会检查 | 结构升级后不能只回滚到只有 7 份文件的旧代码；每批准备保留相同迁移前缀、继续走旧业务的兼容回滚构建，不关闭校验 |
| [initializeDatabase](../server/setup-database.ts) 还会初始化认证与 pg-boss；[迁移入口](../scripts/migrate.ts) 可能原子改写 .env | 先在隔离环境演练完整入口及失败路径；备份认证/队列和私有配置；不能把命令当成只执行业务 SQL 的无副作用工具 |
| [configureRuntimeAccess](../server/database-access.ts) 先撤销 public/pgboss 全部运行授权，再重新授予旧表白名单 | 新表不会自动被授权；未来调整角色设置必须与迁移一起验收且可重复运行，不能事后补一个手工 GRANT 就认定完成 |
| [permissions](../server/permissions.ts)、详情聚合、通知和 Worker 仍以 event/domain 和事件 owner 判权 | M1a 只扩展结构并保持旧业务；完成全部新读取/写入/通知核权前，不开放家长 private、intake、professional 或 NULL domain |
| [M1a](database-drafts/wang-m1a.json) 为 8 张新表、2 张旧表、142 个列定义；[M1](database-drafts/wang-m1.json) 为 20 张新表、10 张旧表、409 个列定义 | 两份都是从 0007 出发的替代草案。实施从 M1a 抽取首批，再生成真实 M1 增量；增量合并后的结构必须与 M1 全量等价 |
| 当前草案全部新表 ENABLE/FORCE RLS，尚无放行策略；业务 CHECK 不覆盖跨行授权 | 未完成角色/策略/服务端事务之前，新表保持运行账号不可用；不靠管理员跑通用例代替受限账号验收 |

首版采用**维护窗口与逐批发布**，不承诺在线无停机迁移。普通索引可在维护窗口创建；如测得锁等待超出预算，另设计非事务并发索引步骤，不能在现有迁移事务中直接使用 CONCURRENTLY。参考 [PostgreSQL 17 CREATE INDEX](https://www.postgresql.org/docs/17/sql-createindex.html)。

| P5 受限读写与事务 | conversation 权限入口、RLS/列权限、原生 JSON 写入边界、输入/状态 CAS、撤权失效、分页/导出/删除/SSE/Worker 适配 | P4 通过；每个调用方有明确模式，独立数据库角色可用 | 本文 A/P/R 场景全部通过；无来源/身份/意愿时关闭能力；只读影子比对无敏感内容扩散，才允许合成账号写入试点 |

P1/P3 只做可加的结构；P2/P4 每一页数据独立事务。P6 不能提前解除 domain NOT NULL、旧来源唯一性等兼容约束；真正开放新域的契约变更在对应适配/回滚验收完成后另审阅。questionnaires、perspectives、note_shares 的退役及 M2+ 练习/预约/研究不在本批删除。

### 结构核对方法

以 0007 静态目录开始，依次应用拟定 P1/P3 的解析结果，再与 M1 manifest/model 比较完整列、类型、默认值、可空性、候选键、FK、CHECK、RLS 和索引。已有检查器只接受从 0007 开始的五份全量草案；实施时须扩展其输入以核对真实批次，不能直接把累计 M1 再执行在 M1a 之后。当前解析结果不是数据库实测。

### 幂等、截止点与恢复

- 每次回填建立固定 run_id、源迁移集合/源码 SHA、截止点、转换器版本和命名空间。映射键使用原 table/PK、event、真实 owner/domain 的结构化唯一组合；新 UUID 一次生成后持久记入受限台账，重试复用，不能每次 random_uuid 重建。
- 台账存于本地私有目录，权限 0600，必要备份与库一起保护；公开报告只给计数/状态和摘要。台账是维护证据，不参与运行期授权；检查目标现有唯一键和源摘要才可复用映射。
- 每页按源主键游标：锁相关根→复核源仍等于截止快照/摘要→写目标及 FK→记录已完成映射→提交。崩溃后同时查目标唯一键和已提交台账；不能只因游标前进就跳过未提交目标。若台账在文件系统，先写预留映射并 fsync、标 pending，事务提交后对账标 complete；pending 必须查目标，不能假定 DB/文件跨介质原子。
- 维护窗口暂停业务写入并处理在途任务。若后续改在线回填，必须先交付同事务双写/变更捕获与一致截止点；只有更新时间扫描不保证删除、撤回和重复请求无丢失。
- 目标值与已存在映射冲突即停止该页，不用 ON CONFLICT DO NOTHING 隐藏不同正文；同 request_id 不同 payload 返回冲突。重复跑第二遍必须零新增、零正文/授权变化。
- 对未知行记录原因和隔离状态。试点集合必须没有未解释行；全量切换前所有有权读取的旧对象都必须完成归属或继续由明确 legacy 适配承担，不能悄悄遗漏。

## 4. 角色和事务边界

| 数据库职责 | 允许的权限 | 明确禁止 |
| --- | --- | --- |
| 运维/迁移身份 | 拟定批次 DDL、显式角色配置、受控备份/恢复 | 不把其连接交给 API/Worker 或前端 |
| 一次性回填身份 | 维护窗口内批准对象的读取/回填；完毕撤销 | 不长期作为普通服务账号，不绕过日志和隔离对账 |
| 现有 reso_runtime | 继续当前 legacy 业务白名单；新表默认拒绝 | 不自动 ALL TABLES 放开新表、不给 DDL/角色成员身份/BYPASSRLS/表所有权 |
| 未来原生 API 职责 | 本人/当前合法参与者范围内 SELECT/INSERT；仅必要根列 UPDATE；版本和审计只追加 | 不改已冻结正文、已签署事实、政策批准或专业资格；普通用户无业务批量 DELETE |
| 未来原生 Worker 职责 | 任务定位到确切 conversation，核验来源/用途/版本，追加 run/decision/tool 与授权输出 | 不能从 event owner 推出他人私人域访问权；不能自行清风险、创建同意、签署或通知家长 |
| 安全/专业与资料清理职责 | 经真实有效 staff_assignments、案件/申请范围和逐动作审计开放最小操作 | 角色字符串/账号展示身份不构成批准；没有真实服务/职责前功能关闭 |

新职责优先复用受限连接校验；当前 assertRuntimeRole 禁止任何角色成员身份，因此不能边给继承组边声称启动校验仍兼容。实施中明确是独立登录角色，还是受审职责接口；不通过放宽管理员校验来适配。

RLS 同时检查可读行和新写行；使用可信会话认证/服务端任务派生上下文，在取得连接后的**同一事务**设置并清理，不使用全局 SET 或客户端传入的 owner/role 作为许可。A 请求提交/回滚后复用同一连接给 B，必须按 B 重新核验；缺上下文一律拒绝。敏感操作仍同时做用途、同意、成员代次、安全状态及业务 CAS 校验，RLS 不代替这些规则。

表所有者和 BYPASSRLS 身份不能用来证明普通用户隔离；无策略的 RLS 默认拒绝，TRUNCATE 等表级操作不受行策略限制，因此运行身份仍不授予此类权限。参考 [PostgreSQL 17 RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)。

跨表核权和写入遵循主体→event→按 ID 排序的 conversations→业务根→版本/授权→任务的既有顺序；模型/外部通知在事务外，发布前再次复验输入、state revision、permission/consent epoch。进入事务后不能换 pool.query 导致校验和写入分属两条连接。

## 5. 必须补齐的隔离验收用例

当前条目是**待实现/待运行验收规格**，没有把源码已有测试或设计反例当成这些用例已通过。复用 createTestDatabase 的随机隔离库、受限角色和 finally 清理，不连接用户业务库。

| ID | 场景/反例 | 验收标准 |
| --- | --- | --- |
| A01 | 0007 空业务库→P1/P3；含数据 0007 副本→逐批升级 | 每批 schema/迁移摘要/候选键/FK 与目标一致；旧列原值和认证/队列可对账 |
| A02 | M1a 之后误执行累计 M1；已执行迁移被改/缺文件/多未知文件 | 安装器在应用 DDL 前拒绝或验证明确增量；启动不能绕过校验 |
| A03 | P1 结构、角色设置或配置落盘失败 | DDL/迁移记录一致回滚；原 .env 仍完整；角色单独事务失败明确标记，不能当全部成功 |
| A04 | 回填同一页重复、中途断连、pending 台账恢复、相同键不同正文 | 原 ID/作者/字节/时间保持；重复零新增；冲突停页并可定位，无半个根指针 |
| A05 | 孤儿 event、跨域 source_message、错误触发/回复消息 | 拒绝关联，不用伪造 ID/修改原文修复；隔离数量真实 |
| A06 | 旧 checkpoint、plan/respond、未知 attempt_no/历史确认范围 | 不恢复原生运行，不虚构阶段/尝试号或全体确认 |
| A07 | 旧 read grant、撤回后重入、当前正文改写但旧快照未改 | 不新增 use_in_agent/跨域许可、不复活旧授权；旧快照哈希不漂移 |
| A08 | 未确认旧理解、专业测试账号、旧关键词危险卡 | 不自动变 confirmed/verified/已接管或风险已解除；缺资源关闭相应能力 |
| P01 | A 是事件 owner，B 是成员且有自己的 private | A 不可读 B 的消息/摘要/列表活动；B 不可读 A private/intake；公开 room 不被私人时间推进 |
| P02 | 逐个数据库角色直接 SELECT/INSERT/UPDATE/DELETE/TRUNCATE/DDL | 未授权表/行/列均拒绝；不能改政策批准/签署/迁移记录；新表缺策略时仍拒绝 |
| P03 | A/B/匿名/Worker 轮流复用 max=1 连接，包含错误、回滚和超时 | 无事务上下文残留；B/匿名不能继承 A；Worker 不能借缺失 actor 扩权 |
| P04 | 入队后撤回/退出/注销，模型结束后再发布 | 旧任务/建议失效，不发布内容；授权变更和失效同事务，SSE/分页/导出也按当前权限过滤 |
| P05 | 新写错误 schema/重键/超限/无证据/错父 kind；伪造已发布政策/Skill | 写入拒绝；policy/rule/body hash、已批准来源及实际执行日志一致，计划不冒充执行 |
| P06 | 新增域的旧 deep link、旧客户端只给 event/domain、批量详情/导出/删除 | 不回退 event owner；不能把 intake/professional 当 private；不漏删旧副本或泄露其他本人域 |
| P07 | 运行角色配置重复执行、顺序重跑后服务再启动 | 原生必要权限仍存在且限范围；不因撤销重授回到全表权限或丢失职责，现有角色检查仍通过 |
| R01 | 尚无原生新写时关开关/部署本批兼容回滚构建 | 旧流程可用，结构保留，全部 migration 校验通过；不执行危险逆向 DROP |
| R02 | 已有原生新记录/撤回/确认/审计后故障 | 先停写保全新数据；不能切回看不懂新记录的旧客户端或只恢复旧备份；按下节修复/重放证据对账 |
| R03 | 从加密备份恢复到独立库并切演练入口 | 认证、队列、旧原文/快照及演练新写均核对；未验证的任务不重放，防止重复回复/外部投递 |

通过阈值：对象计数/原文摘要/作者/版本/撤回状态差异为零；跨域泄露、丢失、伪造同意/签署、重复业务事实为零；隔离集合不得进入试点。锁等待、页尺寸、RPO/RTO 与停机预算**待首次副本演练测量**后填写，不能编造时间目标并宣称达标。

## 6. 回滚与发布决策

| 失败时间 | 执行顺序 | 允许恢复服务的条件 |
| --- | --- | --- |
| DDL 事务未提交 | 由迁移器 ROLLBACK；确认迁移记录、表/列和配置未半更新 | 旧构建及旧迁移集合匹配，原服务验收通过 |
| DDL 已提交、原生仍未写 | 停新入口/回填任务；保留可加结构，部署**携带已执行迁移集合的 legacy 兼容构建**，重新核对角色白名单 | 无新域事实被旧路径遗漏，schema 校验和旧业务通过；不删除 schema_migrations 行伪装降级 |
| 回填部分完成、尚未切流 | 停回填，按 run_id/源键/页状态核对；保留原表；修正转换器后续跑或仅清理可证明属于该 run 且无后续依赖的目标 | 待完成映射不会被读取，旧原文/权限/时间未变；不按“新表为空预期”截断整表 |
| 原生已写/已撤权 | 立即停相关写入与任务发布，保存新事实/审计/队列边界，优先向前修复；无损导出并演练新旧合并后才选兼容退回 | 没有丢弃新增记录或恢复已撤回权限；兼容适配可表达全部已发布事实，否则保持维护状态 |
| 需要备份恢复 | 先恢复到独立库；以备份截止点核对所有后续已提交写入/授权撤回，受控重放可验证业务；验证后才切入口 | 新用户事实不丢失、外部动作不重复；无法证明则不得把覆盖业务库当回滚完成 |

保留每批来源/目标版本、完整代码与迁移文件集、DDL/角色前后摘要、受限回填映射、备份恢复结果、场景结果、未知/隔离计数和操作者决定。正文、token、密钥、真实个案不进入公开证据。
