# Agent 性能优化与验收

2026-11-14，`reso-agent-v4-2026-11-14`。本轮针对实际等待最长的模型串行请求，以及大上下文的重复 JSON 序列化。没有更换模型、降低安全校验、缓存私人答复或新增依赖。

## 保留的改动

1. **最后一次计划同时生成回复。** v3 的普通回合先生成策略 JSON，再请求一段回复文本；工具回合则多一次读取后的决策。v4 在最后一次 JSON 中一起生成策略、待确认建议和自然语言回复，沿用原有输出校验。普通回合通常从 2 次模型调用变为 1 次，工具回合通常从 3 次变为 2 次。
2. **大上下文按编码长度裁剪。** 原实现每移出一条旧记录就重新序列化整个对象。现在仅在超出 32,000 字符时计算各项 JSON 编码长度，按原顺序扣减，最后序列化一次。保持原来的边界、裁剪顺序、最新消息与修正保留规则，输出哈希一致。正常小上下文继续走一次序列化的原快速路径。

工具尚未返回时的临时回复不会发送。模型没提供内联回复时保留原文本生成回退；若服务端修正私聊旁听策略、移除不合适的记录建议，也会丢弃与旧计划绑定的回复并重新生成。非法来源、越权、危险表达绕过、回复修复和确认保存规则不变。Prompt 版本升到 v4，旧版本未完成检查点不会被当成新版本结果复用。

## 真实回复链路测量

测量代码在 [benchmark-agent.ts](../scripts/benchmark-agent.ts)。优化前源码快照保存在 `.data/performance-v4/baseline/`，只包含 server/shared 源码，不含 `.env`。两版共用同一实际 DeepSeek 型号、相同业务 API、同一隔离 PostgreSQL、真实 pg-boss 队列、0.5 秒轮询设置与持久化路径。

四类合成场景（倾听、私人摘要、表达练习、窗口外历史查证）各做 3 对，每对交替先后顺序，共 24 次回合。每次创建独立测试事件，防止检查点复用成为虚假加速。计时从客户端 HTTP 发送开始，经过真实队列和 Worker，到已保存回复的详情 HTTP 返回结束；质量审核在计时结束后执行，不计入耗时。

| 指标 | v3 基线 | v4 候选 | 本组变化 |
| --- | ---: | ---: | ---: |
| 完整回复样本 p50 | 3,183.3 ms | 2,377.0 ms | 降低 25.3% |
| 完整回复样本 p95 | 5,004.4 ms | 3,697.6 ms | 降低 26.1% |
| 平均模型调用次数 | 2.5 | 1.5 | 减少 40% |
| 平均模型输入字符数 | 5,251.3 | 4,189.8 | 减少约 20.2% |

输入字符数不是 token 数或账单费用。12 个样本的 p95 接近最慢样本，不能作为生产 SLA。

各场景每版 3 次的中位数：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 倾听 | 2,536.8 ms | 1,861.3 ms |
| 私人摘要 | 3,097.1 ms | 2,088.2 ms |
| 表达练习 | 4,471.1 ms | 3,617.3 ms |
| 历史查证 | 3,571.0 ms | 2,859.9 ms |

有一对倾听样本反而变慢：1,622.6 → 1,861.3 ms；减少一次请求不保证每次都更快。全部样本、模型调用、回复、草稿、执行轨迹与失败判断保留在 [原始测量](../.data/performance-v4/2026-11-14T13-36-29-801Z/live.json)，[汇总](../.data/performance-v4/2026-11-14T13-36-29-801Z/summary.json)与[日志](../.data/performance-v4/paired-live.log)。本次没有删除慢样本或重新生成失败判定对应的答复。

## 质量约束与负结果

24 次答复的结构、来源、必需工具及“未确认不写业务”硬断言全部通过。独立一次模型调用同时审核同一输入下的两版答复，最初通过 10/12 对。

逐条检查发现，两项判定增加了原准则没有的要求：把一次自愿的情境追问当成强制练习，以及要求私人摘要必须使用第三人称并否定“未保存／不会分享”的边界说明。保留原始失败判定，明确这些评分定义后，只对原有固定输出重新盲序审核全部 12 对，得到 12/12；没有重跑、替换或筛选被测答复。重审文件记录原始文件 SHA-256，可验证计时数据和答复未变：[重审记录](../.data/performance-v4/2026-11-14T13-40-03-838Z/review-replay.json)。

另行运行 10 类真实 DeepSeek 合成行为回归，全部通过，覆盖纠正、摘要、未知感受留空、表达练习、历史查证、实际空目录、计划与事实、拒绝、房间隔离和安全绕过：[结果](../.data/agent-eval/2026-11-14T13-38-35-686Z/results.json)。自动审核使用同一供应商的另一次调用，不能称为独立专家评测，也不能从这组用例推导真实用户效果。

## 上下文序列化测量

两版函数交替调用，预热后各 100 批、每批 10 次。计时只包含序列化函数，输出哈希检查放在计时外。

| 输入 | 优化前 p50 / p95 | 优化后 p50 / p95 |
| --- | ---: | ---: |
| 4,746 字符正常上下文 | 0.0148 / 0.0171 ms | 0.0151 / 0.0175 ms |
| 50,309 字符、需要裁剪 | 1.0658 / 1.1056 ms | 0.2213 / 0.2462 ms |

大输入 p50 降低约 79.2%，正常小输入没有可辨别收益。这是 CPU 微基准，绝对节省不足 1 ms，不将它包装成用户回复加速的主要来源。两种输入输出哈希完全一致；单元回归覆盖恰好 32,000 字符、超出 1 字符、转义、Unicode、空项和不可裁剪输入：[原始数据](../.data/performance-v4/2026-11-14T13-38-06-113Z/serialization.json)。
