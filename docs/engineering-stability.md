# 工程稳定性审查与优化

2026-11-13。审查对象是当前本地多用户 MVP：React Web、Fastify API、独立 Worker、PostgreSQL 与 pg-boss。按单机、少量并发用户评估正确性和恢复能力；另用隔离的合成数据检查查询扩展性。本次没有引入新依赖、微服务或新业务表。

## 审查结论

已修复消息提交与入队分离、数据库连接中断退出、过期错误发布、锁顺序冲突、静默回复重复调用、语音取消崩溃，以及前端请求异常和过期响应处理。数据库连接拒绝、全部连接被终止后，HTTP 健康状态、通知订阅和事务入队可恢复。

这些结果支持当前本地运行和继续验收，不等于生产高可用、模型效果或长期负载验收。

## 已处理的问题

| 优先级 | 触发与问题 | 修复与证据 |
| --- | --- | --- |
| P1 | 消息事务提交后再入队；注入入队失败，HTTP 返回 500，但原消息仍在库中，没有回复任务 | 消息、版本更新与 pg-boss 入队使用同一事务；失败或返回空任务标识均回滚。重复 clientId 不重复入队，显式重试单独建任务。真实受限账号验证 |
| P1 | 单独终止 LISTEN 连接，旧 API 进程以 1 退出；空闲连接错误也无处理 | 通知连接断开后释放并重连，连接池处理空闲错误；关闭时撤销重连并释放连接。实际 pg_terminate_backend 回归与整库连接拒绝／终止恢复测试 |
| P1 | 模型调用期间用户发送新消息，旧调用失败仍插入旧上下文的错误消息 | 成功和失败发布均在事件锁内核对版本及访问资格，过期结果不发布；回归断言没有过期 assistant 消息 |
| P1 | 练习保存先锁 exercises 再锁 events，安全回复顺序相反；持有事件锁时，保存请求占住练习行，另一端 NOWAIT 报 55P03，构成锁环条件 | 问卷、发现、练习和咨询申请统一先锁事件，再访问子记录；锁顺序回归通过 |
| P1 | 已取消的转写请求在 WebSocket 建立前关闭连接；子进程复现未处理 error 并退出 | 建连接前检查取消，先注册错误处理再监听取消；单元测试验证已取消请求不建连接 |
| P1 | HTTP 200 返回 HTML 被当成业务数据；请求无期限等待；断网错误直接冒出 | 非 JSON 成功响应明确拒绝，普通业务请求 15 秒超时、转写 100 秒超时；规范网络错误，保留输入，调用方可取消 |
| P1 | 切换事件或账号后，旧异步响应仍可能更新列表和详情；过期 403 也可能清空新选择 | 会话、列表、详情各自管理请求作用域，取消旧请求且检查作用域后再写状态；401 清理私人状态，操作加同步重复提交保护。作用域和请求测试通过，完整浏览器交互尚未实测 |
| P2 | 成功静默没有 assistant 消息，重复任务会再次调用模型；进程中断会留下 running 记录 | 成功运行记录也参与幂等判断；取得会话排他锁后关闭遗留 running 记录。回归从重复两次模型调用变为一次，并验证中断记录的结束状态 |
| P2 | 停机或会话锁连接丢失后，模型调用仍可能继续，产生失去锁的发布 | 取消信号传至模型；停机、任务到期及锁连接中断停止生成，并阻止发布。注入模型取消和真实锁连接终止均有回归 |
| P2 | SSE 每条通知并行鉴权，慢客户端写入未处理背压 | 同一流串行检查，突发期间只保留最后一个待处理通知，慢读写满时结束流；200 条同步通知的单元场景最多两轮检查、峰值一轮并发，既有真实 SSE 权限测试继续通过 |
| P2 | 健康接口固定宣称数据库正常；通知发送失败会令已提交业务返回失败 | 健康接口实际探测数据库，故障返回 503，并显示通知连接状态；通知降级为定期刷新，不改变已提交写入的成功结果 |
| P2 | 启动失败资源未完整清理；父子进程同时收到 Ctrl+C，重复信号可能中断清理，子进程异常信号退出又被报告为成功 | 队列、连接、监听及端口启动失败路径补清理；退出处理幂等，异常信号保持非零退出码。实际三进程启动与 Ctrl+C 后 API/Worker 均以 0 退出 |
| P2 | 导出分别读取多表，可能混入不同时间的版本；HTTPS 配置仍强制非 Secure Cookie | 导出改为只读 repeatable read 事务；Secure Cookie 根据 PUBLIC_ORIGIN 的 HTTPS 配置启用，受信来源去除空格。导出业务回归和认证配置单元测试通过，未做真实 TLS 浏览器验收 |

业务连接池等待连接最多 5 秒，其 SQL 与空闲事务超时为 15 秒；新回复任务的活动期限为 180 秒。模型单次 HTTP 调用仍为 60 秒，理解与生成分两次调用。数据库故障或锁等待会返回可重试错误，不无限等待。已有旧任务保持原期限；生产扩容或大库迁移前应重新校准这些期限。

任务消费仍是至少一次：若进程在供应商返回后、结果提交前崩溃，重试可能再次调用供应商。数据库消息约束和成功运行检查保证可见回复幂等，不承诺供应商计费恰好一次。遗留运行记录在会话重新获得处理机会时关闭；API 不会擅自判定其他 Worker 正在处理的记录已中断。

## 查询优化测量

0005 只新增三个索引：events(owner_id,updated_at)、有效 members(user_id,event_id)、agent_runs(event_id,domain,trigger_message_id,created_at)。事件查询先合并本人拥有和有效加入的 ID；联系人查询仅对这些事件展开参与者，避免先构造全库参与者集合。

隔离库包含 30,000 个事件、30,000 条运行记录、20 条成员关系；目标用户有 10 个自有事件和 20 个受邀事件。每项执行 7 次 EXPLAIN ANALYZE，报告热缓存中位数；前后结果行数相同。事件列表测量为权限筛选 SQL 片段，未包含最终展示排序或完整 HTTP 请求。

| SQL 片段 | 优化前 | 优化后 | 优化前／后共享数据块访问 |
| --- | ---: | ---: | ---: |
| 事件筛选 | 1.862 ms | 0.054 ms | 430 / 94 |
| 共同联系人 | 14.427 ms | 0.143 ms | 521 / 156 |
| 最新回复运行记录 | 1.106 ms | 0.014 ms | 400 / 3 |

这是合成数据的 SQL 测量，不能解读为真实聊天快了同样倍数。没有测量供应商响应时间、真实网络、冷启动、手机端或持续高并发。私有可复跑脚本及原始结果在 `.data/stability/query-benchmark.ts` 和 `query-before.json`、`query-after.json`。
