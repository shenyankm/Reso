## 第二遍复查发现并一并修正

1. **初始化不匹配**：原来 `{}`／`[]` 默认值与新的必填结构冲突。保留能通过契约的默认值，其余由调用方显式提交完整结构；尚未报告的 followup.outcome 设为 SQL NULL。
2. **重复暂停时间矛盾**：最近恢复时间可以早于再次暂停时间；改为按当前 draft/paused 状态判断，完整历史在交互表。
3. **删字段后遗留索引**：去除 corpus_assets.derived_from_asset_id 与 decision_cases.source_asset_id 的旧索引设计，改由来源关联表反查。
4. **卡片 JSON 冒充关系**：补 assessment/exercise/understanding/invite/application/followup 的真实可空 FK，限定 card_type 与目标组合；候选方法／人员只是展示，不赋权。
5. **生成前清单的循环依赖**：input_manifest 可先记真实获准来源，record_source_id 在决策证据建立后再关联，不要求在生成前伪造尚不存在的决策来源行。
6. **删除请求者后的约束**：合法擦除、去标识和根目标 tombstone 同事务处理；之后可以清空关联，不允许拿去内容 manifest 重新执行请求。
7. **新旧预约配对**：native 的 accepted 提议必须与根的起止和 slot 一致；legacy_time_only 仅用于真实旧导入。
8. **复合外键缺少实际来源列**：直接来源统一使用 source_conversation_id，使 room→private 引用能组成真实 FK；不把目标 private 的 ID 错用为公共消息的所属会话。39 个关键组合关系及其完整父唯一键已结构化并校验。
9. **通知载荷缺少真实目标**：补 appointment/proposal、followup、data_request 的普通 FK；通知 JSON 的 ID／时间／状态必须与真实目标及被冻结事实配对。

10. **回填空值与最终归属混用**：agent_actions／consultation_notes／followups 的 conversation_id 最终必填，只有 expand/backfill 期间临时可空；followup 通知强制 conversation 非空，避免组合 FK 被 NULL 跳过。
