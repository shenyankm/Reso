# 功能 E2E

这些测试补在单元测试和数据库集成测试之外。Android 测试使用生产构建后的 React 页面、真实 HTTP、受限 PostgreSQL 账号、真实 pg-boss 队列和 Worker；模型与语音供应商边界使用可控替身。真实供应商单独验收，不把替身通过计作联调成功。

## 运行

先启动 PostgreSQL、本机开发服务与 Android 调试包。需要已有 `.env`、可建隔离数据库的迁移连接、Android SDK 和已启动的模拟器。修改原生代码后重新构建、安装 APK。`npm run dev` 保持运行，后续命令在另一终端执行。

```sh
npm run db:up
npm run dev
npm run android:build
npm run android:install -- emulator-5554
npm run test:e2e
```

`ANDROID_SERIAL` 可指定其他已安装当前调试包的模拟器，默认 `emulator-5554`。开始时 Reso 应位于 `http://localhost:5173`，且测试专用的 ADB 反向端口 5189 未被占用。测试按序执行，遇到首个功能场景失败就停止依赖它的后续场景，并保留失败证据。

AVD 已安装服务器包时无需切换 APK，可执行 `E2E_APP_ORIGIN=https://openwook.cloud npm run test:e2e`。这个配置只指定需要备份和恢复的原页面；完整回归仍在隔离数据库与 5189 测试入口执行，结束后恢复服务器页面、Cookie 和设备存储，不向线上业务库注入失败或替换供应商配置。公网真实服务需要另用临时账号验收。

原生导出可单独检查，便于定位系统文件保存问题：

```sh
npm run build
node --env-file=.env --import tsx --test e2e/export.test.ts
```

## 覆盖

`android.test.ts` 串起注册、私聊自动建事件、持久队列回复、历史分页、草稿恢复与隔离、回复重试、24 题续答与确认发现、五幕修正及暂停恢复、私人故事、沟通练习、回访、来源理解修正、事件搜索与重要的人、邀请与固定版本分享、撤回与重分享、双视角确认、咨询师与申请人的时间往返、纪要开放及授权撤回、安全卡、成员撤权、原生导出、删除、退出草稿确认和会话失效。

`export.test.ts` 验证原生桥拒绝非法事件 ID 与 UTF-8 字节超限内容、系统保存取消、实际写入文件，并重新读取 JSON 核对事件与内容。测试文件使用唯一名称，读取后删除，不覆盖用户文件。

`profile.test.ts` 验证“我的”入口、昵称保存失败保留与重试、私人记录加载重试／空态／跳回原事件、系统返回、待回访完成后仍保留原记录、按事件原生导出及账号隔离。证据在 `.data/e2e-profile/`；与其他 Android 测试一样使用隔离数据库并恢复原会话。导航与练习入口的行为说明见 [导航调整验收](../docs/navigation-ia-acceptance.md)。

Android 页面首次操作和系统文件选择使用 UI 树坐标。后续页面控件通过 DOM 定位、原生 ADB 键盘激活；每次激活确认真实 click 到达，并等待应用操作结束。文本输入使用 WebView 输入通道，日期和选择框通过标准 DOM 输入事件设置。截图来自 ADB，而非桌面浏览器。测试没有申请或采集真实麦克风：录制用合成音频流验证 MediaRecorder、解码、16kHz PCM、多段上传、错误保留、重试和转入草稿；这一项不代表真实麦克风或真实 ASR 已通过。

## 真实供应商

真实验收需要明确启用，会调用已配置的收费服务，仅发送合成测试文本和本机生成的普通话音频。语音合成使用 macOS 的 `say`（Tingting）和 `afconvert`，不读取用户录音。

```sh
E2E_LIVE=1 npm run test:e2e:live
```

`live.test.ts` 分别验证真实模型的 HTTP→队列→Worker→保存回复，以及真实 PCM multipart→语音服务 WebSocket→识别文字。供应商未配置、授权失败、没有回复或转写不匹配都会失败，不静默跳过。供应商失败不会阻止独立的另一项验收。

## 隔离与恢复

- 每次运行创建随机命名的数据库和受限角色，账号、事件、咨询师资料都属于本次测试；不向原业务库写入测试内容。
- 页面使用 `http://127.0.0.1:5189`，原服务 5173 的映射保持不变。此地址的原生保存权限仅存在于 debug 构建；正式构建不加入该测试地址。
- 备份原页面路由、会话 cookie、localStorage 和 sessionStorage；测试地址已有的存储与 cookie 也单独备份。结束时逐项核对恢复结果。原账户 cookie 不被替换为测试账户。
- 默认测试进程移除真实模型和语音凭据；真实供应商只由单独的 opt-in 命令调用。
- 运行目录在 `.data/e2e/`、`.data/e2e-export/` 或 `.data/e2e-live/`。结果、原生截图、失败页面、结构化服务错误及数据库清理记录都写入独立目录。敏感恢复备份为 0600，恢复核对成功后删除。
- UI 测试遵守真实限流，必要时等下一窗口，不关闭限流。异常服务 5xx 会使测试失败，显式注入的保存或语音失败单独计数。

中断时不要清空 App 数据，也不要批量删除所有 `reso_test_*` 数据库。保留本次目录中的 `session-backup.json` 与 `database.json`。测试没有改动原 5173 映射；重启 Reso 会回到原开发服务。只可按该目录明确记录的数据库、角色和测试状态恢复与清理，不能拿其他测试库当作本次残留。

这套验收不代替实体机、真实麦克风、跨设备并发、正式供应商资质或心理支持效果评估。本机调试 APK 依赖开发电脑服务，服务器调试 APK 直接连接 HTTPS；隔离回归期间的测试入口仍需要开发电脑。

## Agent 建议专项

`agent.test.ts` 使用实际 LangGraph、权限工具、数据库与确认接口，模型仍为明确的测试替身。原生页面覆盖建议来源展示、改写后刷新恢复、503 保存失败保留、确认写入摘要和表达练习、旧建议失效、拒绝回访不写业务记录、确认回访后打开原记录并回看；默认 `test:e2e` 已包含本项。

真实 Agent 行为由 `EVAL_LIVE=1 npm run eval:agent` 单独检查，详见 [Agent 设计与验收](../docs/agent-design.md)。不要把默认 Android 替身通过计作真实模型语义效果。

账户入口专项已纳入 `android.test.ts`：聊天页使用按钮旁的非模态小菜单，验证定位、两项快捷操作、Esc／系统返回／点空白关闭与草稿保留；有底部导航的页面不再显示账户按钮。工作台和退出改从“我的”进入。详见 [账户入口验收](../docs/account-entry-acceptance.md)。

## 模拟对话与可读测试数据

`conversation.ts` 提供一段虚构的亲子沟通情境：小禾与妈妈因复习安排和休息时间发生分歧，逐步澄清感受、准备沟通和暂停方式。主链路接入完整 65 条对话，以小禾／Reso 的身份交替写入，用户消息绑定测试账号；分页同时检查消息数量和双方角色。消息、草稿、故事、表达练习、回访、摘要和房间交流都使用同一情境的自然内容，不再显示 `E2E 历史 20`、`E2E_PRIVATE_STORY` 等占位文字。

默认模型仍为可控替身，按私人、重试和房间情境返回不同自然回复，用于验证稳定的功能链路；它不能证明真实模型的沟通质量。Agent 专项也使用自然语言提出摘要、表达和回访请求，内部以请求内容选择固定建议。故障注入仍保留明确的测试诊断标记。

`experienceTurns` 是另一个 6 轮真实模型体验脚本，覆盖事实、情绪纠正、具体计划、暂停方式和待核对表达草稿。本次已通过服务器 App 的真实输入与发送在原体验账号运行，并保留“和妈妈商量学习与休息（模拟对话）”供继续体验；没有向服务器插入预写的助手回复，也未自动保存或分享表达记录。具体结果见 [模拟会话验收](../docs/conversation-acceptance.md)。

重要理解入口已纳入主链路：65 条未标记历史与普通回复不显示核对按钮，用户消息始终不显示；测试重试生成一条有明确标记的重要推测，验证“这符合你的意思吗？”到不同意、修改和确认的完整链路。组件单元测试覆盖错误、安全提示及建议卡去重，Agent 集成测试覆盖详情、分页与权限。见 [核对入口验收](../docs/understanding-prompt-acceptance.md)。
